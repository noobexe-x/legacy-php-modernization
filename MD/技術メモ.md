# 技術メモ（スタック・構成）

## アプリケーション

- Laravel（Blade + jQuery）、Vite でフロントビルド、`APP_LOCALE=ja` 想定。
- DB: MySQL 8。ローカル Compose では `docker/compose/mysql.yml` のコンテナ。AWS では **RDS**。
- 初期データ: `php artisan db:seed`（`DatabaseSeeder`）。

## Docker（ローカル）

- ルート `docker-compose.yml` は `include` で `docker/compose/*.yml` を結合。
- サービス: `php`（`docker/php/Dockerfile`、entrypoint で `composer install` / `migrate` リトライ）、`nginx`、`mysql`、`node`（任意）。
- `fastcgi_pass php:9000`（`docker/nginx/default.conf`）。
- **AWS + 外部 RDS 用:** `docker-compose.aws.yml` → `php.aws.yml`（MySQL コンテナ非依存）+ `nginx.aws.yml`（ホスト **80**）。

## Terraform（`terraform/`）

- **リージョン:** `ap-northeast-1`（`variables.tf` / `tfvars`）。
- **モジュール:** `network`（VPC・パブリック/プライベートサブネット・単一 NAT・IGW・ルート）、`alb`、`ec2`、`rds`、`s3`、`monitoring`（CloudWatch ログ・アラーム）、`backup`（`count` で無効可）、`route53`（`count`、ホストゾーン必須）。
- **依存の要点:** EC2 セキュリティグループ作成後に RDS（アプリ SG から 3306）。EC2 はプライベートサブネット、**ALB SG からの 80 のみ** 受信。
- **EC2:** Amazon Linux 2023、user data でシステム nginx（プレースホルダ）。IAM: SSM（`AmazonSSMManagedInstanceCore`）。アプリは手動デプロイ。
- **RDS:** MySQL、`publicly_accessible=false`、サブネットグループはプライベートサブネット。
- **機密:** `random_password.db`、output `db_password`（sensitive）。`*.tfvars` は `.gitignore`。

## ネットワーク（論理）

```text
Internet → IGW → パブリックサブネット（ALB、NAT）
プライベートサブネット → NAT → 外向き（EC2 の yum/docker 等）
ALB:80 → EC2:80（ターゲットグループヘルス、パス例 `/`）
EC2 → RDS:3306（セキュリティグループでアプリ SG のみ）
```

## 運用コマンド（抜粋）

```bash
# Terraform
cd terraform && terraform plan -input=false && terraform apply -input=false

# EC2 起動（例）
aws ec2 start-instances --region ap-northeast-1 \
  --instance-ids "$(terraform output -raw ec2_instance_id)"

# SSM
aws ssm start-session --region ap-northeast-1 \
  --target "$(terraform output -raw ec2_instance_id)"
```

## 監視・バックアップ（Terraform 作成）

- CloudWatch: ALB 5xx / UnHealthyHostCount、RDS CPU。ロググループ例 `/laravel-pos/dev/app`。
- AWS Backup: RDS・EC2 ARN を selection に指定（モジュール `backup`）。
